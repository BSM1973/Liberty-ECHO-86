# LIBERTY RELEASE CENTER — iOS / iPadOS
Additive distribution lane, independent of existing macOS Developer ID/PKG/notarization and Windows EXE workflows. No existing desktop workflow or secret is modified.

## Product enrollment
The trusted registry is catalog.json. LOVE EQ is the first product. Each new plugin requires an explicitly reviewed immutable commit with iOS AUv3/Standalone targets, an icon, a compatible scripts/verify_ios_bundle.py and scripts/ios_testflight.sh contract. The current diagnostic passes LOVE_EQ_IOS_BUILD_VERSION because LOVE EQ is the first implementation; subsequent products must adopt this build-version contract or the central adapter must be extended. Do not enroll unported plugins. Keep the product environment ios-<product-key>. Each product owns unique app and AUv3 bundle IDs and provisioning profiles. Use the report from the unsigned diagnostic to register the exact generated identifiers, not a guessed suffix.

## GitHub configuration — central repository only
Repository settings > Secrets and variables > Actions: add the shared iOS secrets IOS_TEAM_ID, IOS_ASC_KEY_ID, IOS_ASC_ISSUER_ID, IOS_ASC_PRIVATE_KEY (raw .p8), IOS_DISTRIBUTION_P12_BASE64 (Apple Distribution certificate AND private key), IOS_DISTRIBUTION_P12_PASSWORD. Use the existing Apple developer team if appropriate; never repurpose Developer ID certificate or notarization password. Do not send private keys through chat or commit them. Use minimum necessary Apple API access.
Settings > Environments: create ios-love-eq, restrict deployment to main and configure required reviewers if available. Add IOS_APP_PROFILE_BASE64 and IOS_AUV3_PROFILE_BASE64 as environment secrets (App Store distribution provisioning profiles for the actual bundle IDs). Future products receive their own environment and profiles; the team and distribution certificate can be reused if valid. GitHub repository secrets are available to other workflows that explicitly reference them; restrict repository write access and review changes to workflows and pinned sources.

## Operations
Push to main touching this new lane triggers an unsigned diagnostic only, no credentials and no upload. Manually run LIBERTY RELEASE CENTER - iOS AUv3 and TestFlight: product love-eq, mode diagnostic. Download identifiers.txt if successful. After Apple App IDs, app record and profiles are set up, run signed-ipa with a unique build number. After validation, choose a new build number and mode testflight to upload, not publish. TestFlight processing and beta testing require App Store Connect access. Release export is not an ordinary sideload package. No real device or App Store acceptance is implied by CI success.
The signing job depends on the diagnostic, runs on a clean runner and uses the same pinned source. It rebuilds using the product signing script. Signing secrets are provided only to that step, not the unsigned build. The reviewed pinned product code must be trusted. The signed IPA artifact includes version metadata and SHA-256. For a product that is already uploaded never reuse a build number. The current SDK check requires 26+ and fails rather than falling back to a stale SDK.
